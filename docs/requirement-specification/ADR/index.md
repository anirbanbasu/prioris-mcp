# Architecture Decision Records

This section holds Architecture Decision Records (ADRs) — settled decisions with named rejected alternatives and the reasoning behind them, extracted out of the Software Requirements Specification (SRS) chapters that depend on them. The SRS states *what* PriorisMCP does; an ADR states *why one particular way of doing it was chosen over the others considered*, so a reader (human or agent) working from the SRS alone never has to read through a discarded alternative just to find the requirement.

Numbering is assigned sequentially at extraction time, in SRS document order (chapter 1 onward) — not by when the underlying decision was originally made. A number, once assigned, is never reused or reordered: a later-reversed decision gets a *new* ADR whose `status` is `superseded-by`, with the superseded ADR's own `status` updated to point forward, rather than editing history in place.

| ADR | Title | Status | Summary |
|---|---|---|---|
| [00001](00001-pdf-parsing-backend-liteparse.md) | PDF parsing backend: `liteparse` over `docling` | accepted | Avoids a PyTorch dependency for v1's PDF-to-Markdown conversion. |
| [00002](00002-html-jats-parsing-pipeline.md) | HTML/JATS parsing pipeline: `html-to-markdown` + vendored XSLT | accepted | Table-fidelity HTML conversion, reused for JATS via XSLT, with two purpose-built fixes over a third-party MathML library. |
| [00003](00003-doi-routing-unsupported-provider-error.md) | DOI routing to an unsupported provider fails, rather than scraping | accepted | A DOI landing outside arXiv/Europe PMC is a hard `unsupported_provider` error, not a scrape attempt. |
| [00004](00004-searchindex-separate-interface.md) | `SearchIndex` as a separate interface from `StorageBackend` | accepted | Full-text search doesn't share `StorageBackend`'s medium-specific infrastructure, so it doesn't share its interface either. |
| [00005](00005-local-file-content-hash-identity.md) | Local-filesystem source identity via content hashing | accepted | No external authority exists to pin a "current version" of caller-sent bytes, so SHA-256 of the content substitutes for `resolve_identifier`. |
| [00006](00006-notes-anchoring-document-level.md) | Notes anchoring: document-level, not span-level | accepted | Span-level note anchors were rejected on four independent grounds; notes anchor to the document as a whole. |
| [00007](00007-notes-export-as-resource.md) | Notes export as a resource, not a tool | accepted | Export reuses the tool/resource split already in the codebase and avoids the server writing to an arbitrary host path. |
| [00008](00008-storage-keys-hashed-not-raw-identifier.md) | Storage keys are hashed, not built from the raw identifier | accepted | The document-hash is `sha256(provider, canonical identifier)`, sidestepping path-traversal/escaping risk entirely rather than mitigating it case by case. |
| [00009](00009-catalogue-sqlite-not-jsonl-replay.md) | Catalogue as SQLite, not append-only JSONL-plus-replay | accepted | A unique constraint plus `INSERT ... ON CONFLICT` gives atomic concurrent writes across multiple local writer processes natively. |
| [00010](00010-fts5-plain-not-external-content.md) | FTS5 as a plain virtual table, not an external-content table | accepted | The source of truth is a separate `markdown` file on disk, which SQLite's `content=''` external-content mechanism can't reference. |
| [00011](00011-global-search-index-not-per-document.md) | One global search index, not one per document | accepted | BM25's IDF term is only meaningful across multiple documents; a per-document index buys no ranking benefit for real file-proliferation cost. |
| [00012](00012-separate-sqlite-files-not-shared-database.md) | Separate SQLite files, not one shared database | accepted | Isolates the disposable `search.sqlite3` cache from durable `catalogue.sqlite`/`manifest.sqlite`, and buys per-document locking, for a measured ~7.3KB/document floor. |
| [00013](00013-notes-search-minimal-not-denormalized.md) | `notes-search.sqlite3` is deliberately minimal, not denormalized like `search.sqlite3` | accepted | Notes never had the "one index per document" problem `search.sqlite3`'s denormalization solves, so it doesn't need the same columns. |
| [00014](00014-notes-export-one-file-per-note.md) | Notes export is one file per note, not one file per document | accepted | Matches the data model 1:1 and follows the Obsidian atomic-note convention over long files with internal anchors. |
| [00015](00015-discovery-openalex-scope-not-multi-aggregator.md) | Discovery scope is OpenAlex `search.semantic`, not a general multi-aggregator expansion | accepted | Fanning out to Semantic Scholar/PubMed/CORE was a false generalisation — none of the three replicate embedding-based `search.semantic`. |
| [00016](00016-research-discovery-new-tool-not-mode.md) | `research_discovery` is a new tool, not a `mode` on `research_search_fetched` | accepted | External not-yet-fetched candidates are structurally incompatible with `research_search_fetched`'s local-corpus result shape. |
| [00017](00017-auto-fetch-oa-pdf-rejected.md) | Auto-fetch of OA PDF URLs is rejected, for now | accepted | Arbitrary OA PDF URLs are an SSRF-shaped trust surface, unlike arXiv/Europe PMC's sanctioned APIs; manual upload already covers the gap. |
| [00018](00018-crossref-pubmed-excluded-from-discovery.md) | Crossref and PubMed are excluded from discovery | accepted | Crossref has no `search.semantic` analog; PubMed is redundant with the existing Europe PMC provider. |
| [00019](00019-semantic-scholar-placement-not-adoption.md) | Semantic Scholar's similarity capability — placement, not adoption | accepted | If adopted, its Recommendations API belongs beside `research_discovery`, not a locally-scoped citation/concept-linking mechanism — the boundary is corpus scope, not algorithm shape. |
| [00020](00020-vector-corpus-topology-two-instances.md) | Corpus topology — two corpus-wide `VectorSearchBackend` instances | accepted | Not one unified type-tagged table (the use case is directional, not merged-ranked), and not per-document (would regress cross-document notes search). |
| [00021](00021-vector-engine-sqlite-vec.md) | Vector search engine: `sqlite-vec` (asg017) | accepted | Chosen over DuckDB+`vss`, LanceDB, ChromaDB, Qdrant Edge, and `sqlite-vector` — license, footprint, and fit with this project's embedded-SQLite pattern and scale. |
| [00022](00022-search-interfaces-stay-separate.md) | `SearchIndex`/`VectorSearchBackend` stay separate interfaces | accepted | Coupling them behind one engine would force any future hosted swap to support every coupled function at once. |
| [00023](00023-embedding-backend-fastembed.md) | Default `EmbeddingBackend` is `fastembed`, not `sentence-transformers` | accepted | Avoids the PyTorch/transformers stack; 1536-dimension "target" rejected as an OpenAI-specific artifact, not a real convergence point. |
| [00024](00024-search-composition-mode-no-server-fusion.md) | Composition: a `mode` parameter, no server-side result fusion | accepted | Rejects both one opaque "smart search" call and an earlier draft's server-side RRF fusion in `hybrid` mode. |
| [00025](00025-index-status-no-separate-tool.md) | `index_status` travels with every search response, not a separate status tool | accepted | A separate status tool would reintroduce the exact ambiguity — empty results with no explanation — it's meant to prevent. |
| [00026](00026-chunk-id-uuid-not-heading-or-offset.md) | Chunk identity is a UUID minted per parse pass, not heading text or position | accepted | Heading text isn't unique within a document; character offset drifts on incidental re-parse differences. |
| [00027](00027-per-provider-domain-prefixed-tools.md) | Per-provider, domain-prefixed tools, not one generic tool parameterised by provider | accepted | A generic `provider`-parameterised tool can't express per-provider identifier/format validation cleanly as one JSON schema. |
| [00028](00028-local-file-content-not-path.md) | Local-filesystem access is via caller-sent content, not a server-side path | accepted | An earlier path-based design assumed client and server share a filesystem, which `streamable-http`/`http` transport breaks. |
| [00029](00029-jats-concurrency-gate-not-anyio-limiter.md) | JATS transform concurrency is bounded by a dedicated gate, not `anyio`'s `to_thread.run_sync(limiter=...)` | accepted | `anyio`'s capacity limiter releases on caller cancellation, not worker completion, so it doesn't bound abandoned-but-still-running transforms. |
| [00030](00030-vector-index-reconciliation.md) | Corpus-wide vector-index reconciliation runs automatically at server startup, not as a tool | accepted | A blocking model-mismatch reconnect gates readiness; unbounded corpus re-embedding runs backgrounded via `lifespan`, never as a caller-invoked tool. |
| [00031](00031-rebuild-progress-failure-visibility.md) | Rebuild progress exposes succeeded/failed counts, not an in-process retry policy | accepted | A failed re-embed left `remaining` stuck forever with no evidence of what happened; a restart, not in-process retry, remains the recovery path. |
| [00032](00032-graph-engine-ladybugdb.md) | Graph search engine: LadybugDB, a native embedded Cypher engine | accepted | Chosen over `graphqlite`, `agentflare-ai/sqlite-graph`, upstream KuzuDB, `Vela-Engineering/kuzu`, and a hosted graph database — native Cypher over a transpiler, accepting a second embedded engine alongside SQLite. |
| [00033](00033-graph-node-shape-pointer-concept-tables.md) | Node shape: two typed tables, `Pointer` and `Concept`, kind is table membership, not a field | accepted | `Pointer` links existing content (chunk/document/note); `Concept` owns its own label/aliases/description; no discriminator field needed. |
| [00034](00034-graph-edge-shape-generic-relationship-table.md) | Edge shape: one generic `MANY_MANY` relationship table, free-text `relation_type` | accepted | No node-pair uniqueness — LadybugDB's internally-generated edge ids make it a native multigraph, so independently-authored relationships never collide. |
| [00035](00035-graph-algorithms-networkx.md) | Graph algorithm backend: NetworkX, not rustworkx or engine-native algorithms | accepted | Algorithms run over a materialized `MultiDiGraph` independent of the storage engine; rustworkx's speed isn't needed at this project's scale, and engine-native algorithms would undermine backend portability. |
| [00036](00036-graph-no-raw-cypher-escape-hatch.md) | No raw Cypher escape hatch, for now | accepted | Every capability gets its own typed method instead of a passthrough query string — reversible if a real need for arbitrary querying emerges. |
| [00037](00037-graph-metadata-merge-conflict-policy.md) | Metadata merge-on-write raises on conflicting values, not silent overwrite or merge | accepted | A second writer's differing value for an existing key raises `MetadataConflictError` instead of silently discarding the first writer's metadata. |
| [00038](00038-graph-concept-dedup-fuzzy-matching.md) | Concept dedup: `find_concepts` uses fuzzy string matching (`rapidfuzz`), not exact/substring matching or embeddings | accepted | Recall-oriented candidate surfacing for the calling LLM to judge — embeddings rejected for missing genuine synonyms and cross-lingual duplicates. |
| [00039](00039-graph-algorithm-surface-fixed-set.md) | Algorithm surface: seven fixed methods, not `shortest_path` alone and not the full NetworkX catalog | accepted | `paths`+`reachable` replace a single optimal `shortest_path`; adds `steiner_tree` and Adamic-Adar link prediction; Louvain for communities. |
| [00040](00040-graph-tool-grouping-op-dispatch.md) | Tool grouping: three op-dispatched tools, not one tool per operation or one mega-tool | accepted | `research_graph_write`/`_query`/`_analyze` group 19 operations by category, keeping `destructiveHint`/`readOnlyHint` accurate per tool. |
| [00041](00041-graph-tools-not-search-fetched-mode.md) | `research_graph_*` are new tools, not a `mode` on `research_search_fetched` | accepted | Graph result shapes are structurally incompatible with `mode`'s uniform matches-list contract — the same reasoning ADR-00016 used for `research_discovery`. |
